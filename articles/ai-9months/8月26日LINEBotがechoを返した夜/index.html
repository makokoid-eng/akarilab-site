8月26日、LINE Bot が echo を返した夜

2026-05-13 · note 原文

連載「触り始めて9ヶ月の記録」第6話

2025年8月26日。

その日、自分はChatGPTで新しいスレッドを立てた。

スレッドのタイトル（後から見るとそう書いてある）は、「LINEボット実装手順」。

それまでのChatGPTスレッドはすべて、感情整理か転職活動か日々の整えのためのものだった。

「実装手順」という言葉を、自分の文脈で初めて使った日だった。

スレッドの冒頭で、ChatGPTがこう書き始めていた。

了解👌 じゃあ「公式LINE × AI活用」について、必要なとこだけ整理して"引き継ぎ資料"っぽくまとめるね。

1. 全体像

LINE公式アカウントを「入り口」にして、ユーザーからのメッセージをAIに渡して返す仕組み。 実装は Messaging API を通じて行う。 基本フロー： ① ユーザーがLINEにメッセージ送信 ② LINEがWebhookでプログラムに通知 ③ プログラムがAI（ChatGPT等）に投げる ④ AIの返答をLINEに返す

「Messaging API」も「Webhook」も、その日初めて見る単語だった。

そして、ChatGPTはこう続けていた。

2. 技術要素（最小構成）

Google Apps Script (GAS) を使うと無料＆簡単 - Webhook受け → メッセージ処理 → LINEへ返信 - LLM呼び出しは UrlFetchApp で OpenAI API 叩く

「GAS」も「UrlFetchApp」も「OpenAI API 叩く」も、初めて見る言葉だった。

それでも、なぜかその夜、自分はやってみることにした。

<!-- ここから先は有料 -->

「GASどうやって使い始めるの？」

スレッドを少し読み進むと、自分のメッセージが残っている。

GASどうやって使い始めるの？

これが、自分の人生で最初の「コードを書くための質問」だった、と思う。

その前まで、ChatGPTにコードを書かせたことは何度もあった。Excelの関数、SQL風のクエリ、Pythonのスニペット。でも、それらは全部「コードをくれ」と頼んで、もらったものを誰かに見せるか、Excelに貼って終わりだった。

「自分がそれを動かす」「自分の手で何かをデプロイする」というイメージは、ずっと持っていなかった。

8月26日は違った。

「GASをどうやって使い始めるのか」を、自分の手で動かす前提で聞いていた。

ChatGPTは丁寧に答えてくれた。Googleアカウントでscript.google.comに行って、新規プロジェクトを作って、コードを貼り付けて、デプロイして、Webhook URLをLINE Developersに登録する、という手順を、一つずつ。

その通りにやってみた。

最初は、何も動かなかった。

「試したけど上手くいかなくて同じエラー出てくる」

スレッドにこう書いてある。

試したけど上手くいかなくて同じエラー出てくる

ChatGPTがコードを直してくれる。 それを貼り付ける。デプロイする。 LINEに「テスト」と送る。 返事が返ってこない。

エラーログを見せる。ChatGPTがまた直す。貼り付ける。デプロイする。LINEに送る。返事が返ってこない。

これを、何回も繰り返した。

スレッドにはこう書いてある。

GASデプロイのコード再度送って

何度も「再度送って」と頼んでいる。

そのうち、自分のメッセージがちょっとイラ立ってくる。

同じことやって何も変わらないのなら何かしら問題あるでしょ？

44歳の人間が、ChatGPTに対して、若干キレている。

でも、不思議と、止めようとは思わなかった。

「諦めて寝る」という選択肢が、その夜の自分にはなかった。

スレッドの後半に、転機が訪れる。

Echoが返ってきた

スレッドにはこう書いてある。

Echoは返ってくるようになった

何が起きていたのかというと、最も単純な「送ったメッセージをそのまま返す Bot（=echo bot）」が、ようやく動いた、ということだった。

自分がLINEに「テスト」と送る。 LINE Bot が「テスト」と返す。

それだけ。

それだけのことに、たぶん、3時間か4時間かかっていた。

でも、その「テスト」が「テスト」になって返ってきた瞬間、自分の世界の見え方は、本気で変わった。

人生で初めて、自分が書いたコード（正確には、ChatGPTが書いて自分が貼り付けたコード）が、自分のスマホの中で動いていた。

「ChatGPTにコードを書いてもらう」と、「自分のLINEに自分のBotが返事を返してくる」は、ぜんぜん違うことだった。

前者は、テキストが画面に出ているだけだった。 後者は、自分の手のひらのスマホの中で、自分の作った何かが応答していた。

それは、コードがどうこうの話ではなく、「世界に対して何かを動かした」という感覚の話だった。

「完全にAIチャット」

Echo が返ってきたあと、スレッドはさらに進む。

ChatGPTのコードを少し書き換えて、受け取ったメッセージを OpenAI API に投げて、その返事を LINE に返す、というところまで行った。

つまり、自分のLINEに「今日の夕食何にしよう」と送ると、自分の作ったBotがChatGPTに聞いて、「今日の冷蔵庫の中身を踏まえると」みたいな返事を返してくる、ということができるようになった。

スレッドにはこう書いてある。

完全にAIチャット

「完全にAIチャット」と本人が書いた瞬間、それはもう、彼にとっては「自分のAIサービス」になっていた。

商用の質ではなかった。バグだらけだった。エラーも頻発した。

でも、「自分の作ったAIが、自分のLINEで動いている」という事実が、44歳の人間の中で、確実に何かを変えた。

この日の意味

この日、コードに触ったことはあった、と前話までで何度か書いた。

ChatGPTにコードを書かせて、Excelに貼ったり、Slack風のチャットボットを作ってみたり、ペライチでLPを作ったり、ということは、もっと前からやっていた。

でも、それらは全部、「コードを使う」ことの話だった。

8月26日は違った。

その日、自分は「コードを動かす」側に立った。

LINE Messaging API という名前を初めて知り、Webhookという概念を初めて知り、GASというツールを初めて触り、UrlFetchApp という関数を初めて使い、OpenAI API のキーを初めて発行し、それらを組み合わせて、自分のスマホで動く何かを作った。

技術書は1冊も読んでいない。プログラミングスクールにも行っていない。GitもNode.jsもまだ知らない。

それでも、Echo は返ってきた。

「コードが書ける」という言葉の意味は、たぶん人によって違う。

ある人にとっては「アルゴリズムが書ける」ことだろうし、別の人にとっては「フレームワークが使える」ことだろうし、別の人にとっては「設計ができる」ことだろう。

44歳の自分にとっての「コードが書ける」の最初の定義は、「自分のスマホで自分の作ったBotが動く」だった。

その定義は、8月26日の夜に決まった。

ここから2ヶ月

ここからGitに最初のコミットをするまで、ちょうど2ヶ月かかる。

その2ヶ月のあいだに、もう少しBotを改造して、食改善Botという名前の自分のプロダクトを完成させ、ChatGPTに「もう少し本格的にやるにはどうすればいい？」と聞いて、Node.jsとVSCodeとGitのインストーラーをダウンロードする日がやってくる。

その話は次回（第7話）にとっておく。

ここで書いておきたいのは、8月26日の夜の「Echoが返ってきた」体験が、その後の全ての土台になった、ということだった。

連載第1話で、台風のホテルで「生成AI」という言葉を初めて知ってから、362日後。

ようやく、自分が「コードを動かす側」になった夜だった。

もし、いまこれから始めるなら

ここからは、いまの自分が、当時の自分に伝えたいことを書く。

最初に動かすコードは、echo bot でいい。

「送ったメッセージをそのまま返す」だけのBot。

何の機能もない、何の価値もない、誰の役にも立たない、ただ自分のスマホに自分のメッセージを返してくるだけのBot。

それでいい。

そのBot が動いた瞬間、世界の見え方が変わる。

「コードが書ける」「コードが動く」「コードがインターネットを介してスマホに届く」という3つを、最小の構成で、自分の手で体験する。

これさえやっておけば、その後の Git やら Cloud Run やら Firestore やらの話は、全部「もう一度別のレイヤーで同じことをやる」だけになる。

最初の echo を、自分の手で動かす。

それが、コードを書ける人生と、書けない人生を分ける、たぶん一番大事な一夜だった、と振り返って思う。

8月26日、LINE に「テスト」と送って「テスト」が返ってきた瞬間が、自分の人生で「コードを書く側」になった、初めての日だった。

次回は2025年10月、食改善Bot を完成させて、Git と Node.js と VSCode のインストーラーを落とした日の話を予定しています。
