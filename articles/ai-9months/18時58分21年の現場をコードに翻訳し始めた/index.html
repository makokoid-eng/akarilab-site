18時58分、21年の現場をコードに翻訳し始めた

2026-05-13 · note 原文

連載「触り始めて9ヶ月の記録」第11話

第10話で書いた「AIが嘘をつかないようにコードを書いた日」（2026年1月26日）から、ちょうど7日後の話。

2026年2月2日、18時58分。

自分は新しいリポジトリを切って、人生で2つ目のプロダクトの初回コミットを打った。

2026-02-02 18:58 Initial commit

このプロダクトの名前は VAC （Value Action Check）。

本業はある外食チェーンの店舗運営で、合計21年。そのうち、店長として毎月やってきた QSC 監査──Q（=料理の品質）・S（=サービス）・C（=クレンリネス、つまり店舗の清潔さ）の評価──を紙のチェックシートで続けてきた期間が、約20年。その作業をコードに翻訳するためのツールだった。

repimemo は「夜の店舗で働く人のための LINE Bot」だった。

VAC は「自分の本業の現場で、自分が20年やってきた仕事のための LINE Bot」だった。

つまり、自分にしか作れないものを、初めて自分の手で作り始めた夜だった。

<!-- ここから先は有料 -->

8時間で MVP に到達した

最初の Initial commit から、翌日2月3日の02時54分まで、約8時間。

その間の8コミットを並べると、こうなる。

2026-02-02 18:58 Initial commit 2026-02-02 19:21 add: stores master with storecd 2026-02-02 19:27 add: template items (trial 5) 2026-02-02 19:51 chore: rename categories (no abbreviations) 2026-02-03 01:15 feat: add minimal line webhook server 2026-02-03 01:30 fix: normalize package.json for cloud run 2026-02-03 02:43 chore: update ui labels (cleanliness -> クレンリネス) 2026-02-03 02:54 feat: full 5-step QSC flow with evidence rule and scoring

stores master with storecd というのは、自分の担当している4店舗のマスタデータ（店舗コード付き）を最初に入れた、ということ。

これが、第6話で書いた echo を返した日と、決定的に違うところだった。

echo を返したときは、ChatGPT に「動くだけの最小のBot」のコードをもらって、何も知らないまま動かした。

VAC は違った。

「店舗マスタ」「店舗コード」「QSC」「クレンリネス」「監査」「証拠（エビデンス）」。

これらの単語は、エンジニアの世界では「ドメイン用語」と呼ばれる、特定の業界に固有の言葉だった。

そして、これらの単語の意味を、自分は20年かけて、現場で覚えていた。

ChatGPT に「ドメインモデルを作って」と頼めば、ChatGPT は汎用的な「店舗管理システム」を作ってくれる。

でも、自分は「店舗マスタ」と「店舗コード」が、実務でどう紐づいているか、知っていた。

その知識を、ChatGPT に渡しながら、コードを組み立てていった。

「cleanliness -> クレンリネス」のリネーム

8コミット目のひとつ前、02時43分のコミットが、いま振り返るといちばん象徴的だった。

02:43 chore: update ui labels (cleanliness -> クレンリネス)

UI のラベルを「cleanliness」から「クレンリネス」に変更した、というコミット。

ChatGPT に最初にコードを書かせたとき、品質評価の3項目は英語で「Quality / Service / Cleanliness」になっていた。

エンジニア的には、それでよかった。

でも、自分の現場では、20年間ずっと、店長も社員もアルバイトも、「クレンリネス」というカタカナで呼んでいた。

「英語で『Cleanliness』と書いてあるシステムは、現場では使われない」

これは、エンジニアではない自分が、現場で20年積み上げた直感だった。

だから02時43分、ラベルを「クレンリネス」に直した。

ChatGPT は「Cleanliness の方が正しい英語表記です」と言ったかもしれない。でも、自分は「いや、クレンリネスでいい」と返した。

これが、自分のプロダクトに、自分の現場の言葉を残す、最初の操作だった。

5-step QSC flow with evidence rule and scoring

その日の最後のコミット、02時54分。

02:54 feat: full 5-step QSC flow with evidence rule and scoring

「5ステップの QSC フロー、証拠ルール、採点ロジック込み」。

これがその夜の MVP（=動く最小の本番版）だった。

5ステップというのは、QSC 監査を5つの段階に分けた構造のこと。

「料理の温度を確認する → 店内の動線を見る → クレンリネスをチェックする → スタッフの応対を観察する → 売場の整え方を見る」のような流れを、5つの場面に切り分けて、それぞれで質問に答えていく、という形式。

これは、自分が紙のチェックシートで20年やってきた作業の構造を、そのままコードに写したものだった。

「証拠ルール」というのは、評価項目には必ず写真エビデンスをセットで残す、というルール。

これも、現場で「言ったもの勝ち」「主観でしか採点できない」という問題に20年苦しんできた結果、自分が辿り着いた工夫だった。

「採点ロジック」は、各項目に重み付けをつけて、店舗全体のスコアを出す仕組み。

これも、20年で何度も改良してきた、自分の頭の中にしかなかった採点方式だった。

8時間で MVP に到達したのは、コードを書く速度が速かったからじゃなかった。

頭の中にすでに「設計」が20年分あって、それを ChatGPT に翻訳しながら打ち込んでいただけだった。

自分が両側に立てたこと

もし、これを、エンジニアに頼んで作ってもらおうとしたら、何が起きていたか。

エンジニアは「店舗管理システム」「QSC アプリ」「監査ワークフロー」みたいな汎用語で要件を聞いてくる。

そして、「クレンリネスって何ですか？英語だと cleanliness ですよね？」と確認する。

「いえ、現場では『クレンリネス』とカタカナで呼んでます」と答える。

「では UI にもカタカナで『クレンリネス』と入れますか？」と確認する。

「はい」と答える。

「ドキュメントには cleanliness、UI にはクレンリネス、で良いですか？」と確認する。

このやり取りが、何ターンも続く。

その時間が、自分にはなかった。

自分の中では「クレンリネスはクレンリネスだ」が当たり前だった。エンジニアにとっては当たり前じゃない、ということ自体が、自分の中で言語化されていなかった。

これは、エンジニアが悪いんじゃない。

ドメインの中で20年生きてきた人と、ドメインの外から見ている人で、「当たり前」が違うのは、当たり前のことだった。

VAC は、その「当たり前の違い」を、自分が両方の側に立つことで、一気に消した結果だった。

44歳のエリアマネージャーが、自分の手でコードを触れるようになって、初めて作れる種類のものだった。

ここから3ヶ月

VAC は、この夜の MVP から、3月、4月にかけて急速に育っていった。

3月2日には prod と beta の環境を切り分け、3月3日には Firestore に監査結果を保存するようになり、その後、本部Bot と店舗Bot の2系統に分かれ、PWA 化（=モバイルでアプリのように使える形式に）された。

そしていま、VAC は自分の担当4店舗で、実際に毎月の QSC 監査に使われている。

その話の続きは、第12話以降で書く。

もし、いまこれから始めるなら

ここからは、いまの自分が、当時の自分に伝えたいことを書く。

自分が「素人」の業界に手を出すのではなくて、自分が一番詳しい業界のために、最初のプロダクトを作る。

これが、ノンエンジニアの最大の強みだった。

エンジニアは、技術が強い。

でも、エンジニアは、ふだん自分が働いていない業界のドメイン用語を、深くは知らない。

自分は、技術は弱い。

でも、自分が20年いた現場の用語と、その用語の裏にある実務の流れを、深く知っていた。

その差分が、VAC を MVP まで8時間で到達させた。

これから個人開発を始めたい人に伝えたいのは、最初の1本は、自分が一番詳しい業界のために作る、ということ。

技術的に新しいことをやろうとしない。

自分が現場で20年使ってきた言葉を、そのままコードに翻訳する。

それが、エンジニアには真似できない種類の価値を、自分のプロダクトに乗せる、いちばん速いやり方だった。

「クレンリネスはクレンリネスでいい」

この一行を、ChatGPT の提案を超えて、自分の判断で書ける。

それが、ノンエンジニアの個人開発の、たぶん核心だった。

次回は2026年4月、19日のあいだに4つのプロダクトを立ち上げた話を予定しています。
