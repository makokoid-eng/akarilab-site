食改善Bot が動いた10月、ようやく開発者の道具を揃えた

2026-05-13 · note 掲載版

連載「触り始めて9ヶ月の記録」第7話

2025年10月6日、16時25分。

自分のGoogle Driveに、こんなファイルが残っている。

食改善Bot－PROD.gscript

「PROD」というラベルを、自分のファイル名に初めてつけた瞬間だった。

「PROD」というのは、エンジニアの世界では「production」つまり「本番運用版」という意味で、開発中のものと本番用のものを区別するために使う言葉だった。

それを、44歳の自分が、生まれて初めて、自分のファイル名にくっつけた。

このBotは、第6話で書いた「8月26日にEchoが返ってきた夜」から、ちょうど41日後に、本番運用できるレベルにまで育っていた。

そして3日後、10月9日18時33分には、データベース用のGoogleスプレッドシートを作っていた。

FOODCoachDB.gsheet

これも自分のGoogle Driveに残っている。

そしてそのまた6日後、10月15日16時32分、自分はそのスプレッドシートをコピーして、バックアップを取っていた。

FOODCoachDB のコピー.gsheet

「バックアップを取る」という発想を、自分のデータに対して、その日初めてやった。

それまで、エクセルとかワードとかパワーポイントとか、仕事のファイルでもバックアップを意識的に取ったことは、たぶん一度もなかった。

でも、自分の作ったプロダクトのデータには、なぜか反射的にバックアップを取った。

<!-- ここから先は有料 -->

「食改善Bot」が何だったのか

このBotの中身を、いま正直に振り返ると、よく覚えていない。

ファイル名から推測すると、食事ログを LINE で投げると、データベースに記録して、栄養価とかを返してくれる、そんな仕組みだったと思う。

8月26日に最初の echo（=送ったものをそのまま返すだけの最小機能）を動かしたあと、自分はその echo を改造して、「LINEで自分に送ったメッセージをAIに渡して、AIの返事を返す」というところまで進めていた。

そこから、「ただ AIに渡すだけじゃなくて、データを保存できるようにしたい」という発想になって、Google Sheets（=Google提供の表計算サービス、エクセル相当）にデータを書き込む仕組みを追加した。

それが、食改善Bot だった。

商品としては誰にも公開していない。LINEのチャネルとしても、自分しか使っていない。

でも、自分にとっては、初めて「PROD」と名前をつけられる、自分のプロダクトだった。

自分でラベルをつけた瞬間

このプロダクトに「PROD」とつけた瞬間、自分の中で何かが変わった、と思う。

それまで、自分が触っていたコードは、全部「実験」だった。

エラーが出る。直す。動く。改造する。壊れる。直す。

その繰り返しの中で、いつ「実験」が終わって「本番」になるのか、ぜんぜん分からなかった。

でも、10月6日のその日、自分は「これはもう本番だ」と決めた。

「PROD」というラベルを、自分の判断でつけた。

これは、技術的な意味では何もしていない。ただファイル名にハイフンと4文字を足しただけ。

でも、心理的な意味では、自分が「アマチュアの実験者」から「自分のプロダクトを持つ人」に切り替わった瞬間だった。

エンジニア界の作法をまだ何も知らない44歳が、ChatGPTがどこかの記事から教えてくれた「PROD」という言葉を、見よう見まねで自分のファイル名に貼り付けた。

それが、最初の「自分は作る人だ」という宣言だった。

それから17日後、Node.js のインストーラー

ここからの2週間、自分は食改善Bot を運用しながら、ChatGPT に「もう少し本格的に開発するには何が必要？」と聞き始めていた。

その答えは、当時の自分にとって、ほぼ呪文だった。

「Node.js を入れてください」 「VSCode という統合開発環境を使うと便利です」 「Git でバージョン管理してください」 「GitHub というサービスがあります」 「GAS でできることは限られているので、本格的に作るなら別のサーバーを使う必要があります」

そう言われて、何のことかよく分からないまま、ChatGPT に「じゃあ、それを順番にやるためのリンクをください」と頼んだ。

そして10月23日14時39分、自分は Node.js のインストーラーをダウンロードした。

node-v22.21.0-x64.msi

そこから1週間、Node.js を入れたものの、何をすればいいかよく分からないまま、過ごしていた。

VSCodeUserSetup-x64-1.105.1.exe Git-2.51.2-64-bit.exe

ダウンロードフォルダの記録によると、自分が VSCode と Git のインストーラーをダウンロードしたのは、10月30日の16時36分と16時56分だった。

つまり、20分間隔で、立て続けに2つのインストーラーをダウンロードした。

おそらく ChatGPT に「VSCode はどこからダウンロードする？」と聞いて、リンクを開いてダウンロードして、続けて「Git はどこ？」と聞いて、もうひとつダウンロードした。

20分。

44歳の人間が、人生で初めて、自分のパソコンに開発環境を構築した、その全部のセットアップが、20分間に集中していた。

なぜこの順番だったか

いま振り返ると、自分が「GAS だけ」の世界から「Git・Node・VSCode の世界」に踏み出したのは、必要だったからだった。

食改善Bot は GAS で動いていた。GAS は Google が提供する無料のサーバーレス環境で、簡単な Bot を動かすには十分だった。

でも、GAS だけだと、できないことがいくつか見えてきていた。

複雑なロジックを書くと、GAS のエディタは見づらかった。 複数のサービスを連携させるには、GAS の制約が窮屈だった。 コードのバージョンを管理する仕組みが、GAS のエディタにはなかった。 本格的な Web アプリにスケールするには、別のサーバーが必要だった。

その「窮屈さ」を実感していたから、Node.js と VSCode と Git を入れた。

これが大事な順番だった、と思う。

最初に道具を揃えていたら、たぶん使い方も分からないまま、道具に振り回されていた。

最初に作ってみて、作っているうちに「これじゃ足りない」と分かって、その上で道具を取りに行った。

道具に主導権を渡さなかった。

その日の夜

10月30日の夜、Git と VSCode をインストールしてから数時間後、自分は人生で最初の git commit というコマンドを叩いた。

そして、最初の Git リポジトリ（=Gitで管理されるコードの保管庫）に、最初のコードを置いた。

そのコードは、これまで GAS で書いてきた食改善Bot ではなく、別の Bot のプロトタイプだった。

そのBotの名前は repimemo といった。

repimemo の話は、次回（第8話）にとっておく。

ここで書いておきたいのは、食改善Bot で「自分のプロダクトを動かす」という体験を1ヶ月積んだあとに、ようやく「Git・Node・VSCode」という開発者の道具を揃えた、ということだった。

もし、いまこれから始めるなら

ここからは、いまの自分が、当時の自分に伝えたいことを書く。

最初から Git や Node.js や VSCode を入れる必要はない。

GAS だけで、十分に「自分のプロダクト」は作れる。

実際、自分はそれで2ヶ月、自分のLINE Bot を動かしていた。動かしているうちに、「これじゃ窮屈だ」という感覚が、自分の中から自然に出てきた。

その「窮屈さ」が、Git や Node.js や VSCode を取りに行く動機になった。

逆に、その「窮屈さ」を感じる前に、開発者の道具を一気に揃えると、使い方が分からないまま放置することになる、たぶん。

最初に必要なのは、動くものを1つ作ること。

その1つを動かしているうちに、自分の中に「もっと色々やりたい」という気持ちが芽生える。そのときに、初めて本格的な道具を取りに行く。

道具に主導権を渡さない。

自分の作りたいものが主導権を持つ。

44歳の自分が、食改善Bot を 1ヶ月運用してから、ようやく Node.js のインストーラーをダウンロードしたのは、結果として、いちばん遠回りに見えていちばん効く順番だった、と振り返って思う。

10月6日、自分のファイル名に初めて「PROD」と書いた日が、その全部の始まりだった。

次回は2025年10月30日、人生で初めて git commit というコマンドを叩いて、repimemo というLINE Bot を GitHub に置いた日の話を予定しています。
