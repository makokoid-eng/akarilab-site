2026年4月2日、12時23分。

自分は新しいリポジトリを切って、3つ目のプロダクトの初回コミットを打った。

2026-04-02 12:23 Initial commit

このプロダクトの名前は moyalog（もやログ）。

それから18日間で、自分は4つのプロダクトのリポジトリを次々と立ち上げる。

2026-04-02 12:23 moyalog 2026-04-11 18:25 hidamari 2026-04-15 14:57 okilockle 2026-04-20 22:02 makochinta1-poster

これに、4月8日に立ち上げた AkariLab のランディングページのリポと、4月19日に立ち上げた note 記事自動化のリポを足すと、合計6つ。

18日間で、6つのリポを切った。

そして、それぞれの「立ち上げから動くまでの時間」が、回を追うごとに短くなっていった。

moyalog、2時間で MVP

4月2日12時23分の moyalog の初回コミット。

それから1時間4分後の13時27分に、こんなコミットが入っている。

2026-04-02 13:27 MVP: 感情フロー + AI鏡返し + Firestore(分割設計)

2時間で MVP（=動く最小の本番版）に到達した。

感情フロー、AI鏡返し、Firestore（=Googleのデータベース）保存。これが「もやログ」の中核機能だった。

もやログというのは、自分のもやもやした気持ちを LINE に投げると、AI が「鏡」のように整理して返してくれる、というプロダクト。

第3話で書いた「2025年2月4日にAIDaigoにジャーナリングを手伝ってもらった夜」を、自分以外の誰かに渡すために作ったプロダクトだった。

実は、この日のコミットを並べると、1つだけ気になるものがある。

13:29 remove: 秘密鍵をリポジトリから除去

13時27分にMVPを上げて、その2分後に「秘密鍵を除去」している。

これは、誤って Firebase の秘密鍵を GitHub に push してしまい、慌てて消した、ということだった。

エンジニアなら誰でも一度はやる失敗だった。

44歳の自分も、ここで初めてその「初心者の通過儀礼」をやっていた。

ただ、ここで大事だったのは、2分で気づいて2分で削除できたこと。これは、第8話・第9話の「GCP IAM 権限地獄」で、自分が「セキュリティに関するコミットは即時対応する」という習慣を、たぶん身につけていたからだった。

hidamari、1時間で5機能

4月11日18時25分、hidamari のリポを切った。

2026-04-11 18:25 初期構築：オンボーディングフロー（先生選択学年教科書） 2026-04-11 18:33 GitHub Actions自動デプロイ設定 2026-04-11 18:55 AI対話統合：そうま/かいとが算数を教える 2026-04-11 19:06 LaTeX禁止ルール追加 2026-04-11 19:09 LaTeX禁止ルール：エスケープ修正 2026-04-11 19:15 エンコーディング修正・LaTeX禁止 2026-04-11 19:26 計算検算ルール・学年別問題レベル・フォロー時会話クリア

18時25分から19時26分まで、1時間1分で7コミット。

オンボーディングフロー（先生選択・学年・教科書）、自動デプロイ、AI対話統合、LaTeX禁止ルール、計算検算ルール、学年別問題レベル、フォロー時会話クリア。

これは hidamari という、子ども向けAI学習Bot の最初の1時間だった。

「LaTeX禁止」というコミットメッセージが3つ並ぶ。

LaTeX（=数式の標準的な書式）でAIが数式を返すと、LINEの画面では \frac{1}{2} のような生のテキストとして表示されてしまう。子どもには読めない。

「AIにLaTeXを使わせない」というルールを最初のうちに入れた。

これは、moyalog や repimemo を作ってきた経験で「AIの出力をそのまま信用しない」習慣（第10話）がついていたから、すぐに気づけたことだった。

1時間で5機能を実装する速度は、技術が速くなったからじゃない。

「何が壊れやすいか、最初の段階で予想できる」という直感が、自分の中に少しずつ積み上がっていたからだった。

okilockle、49分で過去経験フル活用

4月15日14時57分、okilockle のリポを切った。

2026-04-15 14:57 feat: initial project setup - Okilockle beta 2026-04-15 15:09 fix: node version 20 -> 22 for Cloud Run buildpack 2026-04-15 15:16 fix: use env vars for tokens on Cloud Run 2026-04-15 15:20 fix: set env vars during deploy, not after

14時57分から15時20分まで、23分で初期セットアップ完了。

最初の feat: initial project setup から12分後に、もう「Node version 20 -> 22」という修正が入っている。

これは、Cloud Run の Node.js 環境のバージョン違いで動かない、という、自分が2月のVACで踏んだ問題と全く同じだった。

「同じ失敗は二度しない」を、もう自分は身につけていた。

15時16分、15時20分の「env vars」コミットも同じ。本業向けのLINE Botを Cloud Run にデプロイするとき、環境変数の管理で何度か詰まったことがあった。

その教訓を、okilockle で最初の30分のうちに全部適用していた。

okilockle というのは、本業の店舗で、出勤報告を LINE に投げると記録してくれる、自分の現場向けのツールだった。

現場のスタッフが、勤怠用の別アプリを開かなくても、普段使っている LINE のなかで報告が完結する。これも第11話の VAC と同じく、現場の人の「いつもの動作」をそのまま使う設計だった。

VAC（第11話、QSC監査）に続く、2つ目の「本業向けプロダクト」。

makochinta1-poster、自分のための拡散装置

4月20日22時02分、makochinta1-poster のリポを切った。

2026-04-20 22:02 初期コミット：makochinta1 X自動投稿（note連携）

これは、AkariLab で書いた note 記事を、別の X アカウント（makochinta1）から自動で引用ツイートする仕組みだった。

つまり、自分が書いた note 記事を、自分が読まれるように、自分の書いた自動化スクリプトで宣伝する、という、完全に自己完結したループ。

この連載「触り始めて9ヶ月の記録」の第1話・第2話・第3話と続けて、いま読んでくれている人のうち何人かは、たぶん、makochinta1-poster が引用ツイートを流したのを X で見て、ここに来ている。

つまり、いまこの記事を読んでいる人の存在自体が、4月20日22時02分の自分の作業の延長線上にある、ということだった。

立ち上げ速度の話

18日間で6つのリポ。

それぞれの「立ち上げから MVP までの時間」を並べると、こうなる。

  • VAC（2月2日、第11話）: 8時間
  • moyalog（4月2日）: 2時間
  • hidamari（4月11日）: 1時間で5機能
  • okilockle（4月15日）: 49分で初期セットアップ完了

4ヶ月で、10倍速くなっていた。

技術が速くなったわけじゃない。

「同じ失敗を二度しない」「同じ設定ファイルを再利用する」「同じパターンを真似る」「同じ落とし穴を避ける」。

これらが「立ち上げ筋肉」として、自分の中に積み上がっていた、ということだった。

特に、4月の18日間で立ち上げた4つのプロダクトは、全部 LINE Messaging API + Cloud Run + Firestore + OpenAI API という同じ技術スタックの組み合わせで動いていた。

最初の1つ（repimemo）で22時間かかったクラウド設定が、4つ目（okilockle）では23分で終わっていた。

速くなった理由は、AIが勝手に全部作ってくれたからではなかった。

AIに渡す前提、避けるべき落とし穴、最初に入れる設定、壊れやすい場所を、自分が少しずつ覚えていたからだった。

もし、いまこれから始めるなら

ここからは、いまの自分が、当時の自分に伝えたいことを書く。

個人開発は、1個目の完成度より、2個目以降の立ち上げ速度のほうが大事。

1個目を完璧に作ろうとして、5ヶ月かけて1個しか出せない人と、 1個目は2ヶ月で雑に出して、その後の3ヶ月で3個出す人。

後者のほうが、たぶん遠くまで行く。

理由はシンプルで、2個目を作るときには1個目で踏んだ全部の地雷を避けられるから。

3個目を作るときには2個目までの地雷を避けられる。

そして、地雷を避ける時間が短くなった分だけ、自分の現場のドメイン知識（第11話）を、プロダクトに乗せる時間が増える。

「同じ失敗を二度しない」という当たり前の原則が、個人開発では爆発的に効く。

1個目をきれいに作る、より、1個目をさっさと出して2個目に行く。

それが、4月の18日間で自分が学んだ、いちばん大事な習慣だった。

次回は最終話。「触り始めて9ヶ月、5プロダクト並走の今、見えてること」を書きます。
