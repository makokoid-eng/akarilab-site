# 設計md：akarilab.org 直接決済（Stripe Payment Link ＋ Invoicing）

- 起票日：2026-07-06
- ステータス：ユーザー承認済み設計（実装前）
- 方式：案1（Payment Link 方式）を採用。埋め込みチェックアウト（案2）はサーバー必須のため却下

## 目的

- 30分相談をココナラを経由せず akarilab.org から直接カード決済で受け付けられるようにする
- 受託案件（Excel/VBA 等）に請求書払い（Stripe Invoicing：カード・銀行振込）を用意する
- 領収書は Stripe の決済完了メール（自動送信）で発行する

## Stripe 側（Claude が MCP 経由で作成）

1. 商品「業務の自動化 現場目線相談（30分）」
   - 価格：4,400円（税込）※ココナラの 4,000円（税抜）と同額
   - Payment Link を発行、領収書メール自動送信を有効化
2. 受託案件は商品化しない。案件確定のたびに Stripe Invoicing で請求書メールを個別送付（サイト実装なし、運用のみ）

## サイト側の変更（3点のみ）

1. `/r/stripe-consult/` 中継ページを新設
   - 行き先＝Stripe Payment Link。既存の /r/ 流儀に合わせ、redirect-monitor の週次クリック計測に乗せる
2. `/makoto/services/index.html`
   - 30分相談の項に「カードで直接申し込む」ボタンを追加（リンク先は `/r/stripe-consult/?from=services-hub&ch=akari`）
   - 受託系の項に「請求書払い（カード・銀行振込）に対応」の一文を追記
3. `tokushoho.html`
   - 決済手段に「クレジットカード（Stripe）／請求書払い（銀行振込・カード）」と支払時期を追記

## ブランド分離・規約ガード

- 個人名が出る決済導線は `/makoto/` 配下と特商法ページに閉じる。ひだまり／もやログ／りぴメモ等のプロダクトページには決済導線を置かない
- ココナラ規約対応：ココナラ経由の顧客を直接決済へ誘導しない。ボタン文言は「ココナラを使わない方はこちら」等の並列の入口とし、ココナラのサービスページ・メッセージから直接決済リンクへは一切誘導しない

## 検証

- 中継ページのリダイレクト動作をローカルで確認
- Payment Link をテスト表示（実決済はしない）し、金額・商品名・領収書設定を目視確認
- sitemap.xml / llms.txt への `/r/` ページ追加要否は既存 /r/ ページの扱いに合わせる（既存が載せていなければ載せない）
